# NetBird Infrastructure Security Hardening & Zero-Trust Access Guide

This document presents security best practices, cryptographic specs, key rotation procedures, firewall hardening, and access control policies for NetBird.

---

## 1. Cryptographic Standard & Encryption

NetBird relies on standard WireGuard primitives for data channel privacy:
- **Cipher Suite:** ChaCha20 for symmetric encryption, Poly1305 for authentication.
- **Key Exchange:** Curve25519 for ECDH key exchange.
- **Hashing:** BLAKE2s for hashing.
- **Quantum-Safe Option:** Supports Rosenpass (post-quantum key exchange extension) for high-security environments.

---

## 2. Zero-Trust Network Access Control (ZTNA)

1. **Default Deny Policy:** Configure NetBird ACL policies so nodes cannot interact across mesh subnets unless explicitly permitted by security group policies.
2. **Setup Key Expiration & Usage Limits:**
   - Single-use setup keys for automated node provisioning.
   - Set key expiration to maximum 24 hours.
3. **Multi-Factor Authentication (MFA / SSO):**
   Integrate OIDC providers (Zitadel, Keycloak, Auth0, Google Workspace, Okta) to enforce MFA and periodic re-authentication.

---

## 3. Host Firewall Hardening (UFW / iptables)

Execute `./security/firewall_rules.sh` to enforce strict ingress filtering.
Only open public UDP/TCP ports required for gRPC signaling and WireGuard tunnels.

---

## 4. Key Rotation & Secret Hygiene

- **WireGuard Peer Keys:** Automatically regenerated by NetBird client daemon upon re-authentication.
- **Coturn Shared Secret:** Rotate every 90 days in `config.yaml` and `turnserver.conf`.
- **Database Backups:** Ensure backup archives are encrypted using AES-256 (`gpg -c`).
